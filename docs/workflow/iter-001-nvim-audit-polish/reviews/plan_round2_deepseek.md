## BLOCKER — the new dashboard expiration rule kills the `nvim .` dashboard it is supposed to verify

`plan.md:134` adds: "if `vim.fn.argc() > 0` … → set `vim.g.opened_dashboard_on_startup = true` and `return true`". For `nvim .`, `argc()` is 1 (the directory is an argument), so the first `VimEnter`/`BufEnter` invocation deletes the autocmd before the dashboard can ever open. That directly contradicts the plan's own verification at `plan.md:174` ("verify `nvim .` opens dashboard beside Neo-tree") and regresses the documented feature: `dashboard-startup-fix.md:1-8,139-142` defines the whole purpose as "launching Neovim with a directory argument → neo-tree left, dashboard right". The mechanism it depends on is real: AstroNvim opens neo-tree for directory buffers (`AstroNvim/lua/astronvim/plugins/neo-tree.lua:30-50`), and neo-tree's netrw hijack replaces the directory buffer with a blank buffer (`neo-tree.nvim/lua/neo-tree/setup/netrw.lua:52-63`), which is the window `snacks.dashboard.open({ buf, win })` fills.

A second clause has the same effect if the check runs before the hijack: the directory buffer is "named" (its name is the directory path), so the "named/modified/non-empty" test independently expires the listener.

Required change: drop the `if vim.fn.argc() > 0` clause — the buffer-state scan already covers `nvim README.md`, since that buffer is named — or restrict it to non-directory arguments (`vim.fn.argc() > 0 and vim.fn.isdirectory(vim.fn.argv(0)) == 0`), and exempt directory-named buffers from the "named" test (`vim.fn.isdirectory(name) == 0` / `buftype == ""`).
